## Keyboard repro pass (2026-09-04, issue #567)

Issue #567 was reported as "dropdown selects are not keyboard-operable", with the repro pass left open: is it every `Select`, or specific screens? The answer turned out to be neither.

**The shared `Select` is fine.** `src/components/ui/select.tsx` is upstream shadcn `base-nova` over Base UI 1.7.0, with one local addition (`collectSelectItems`, which derives the `items` prop from children so `SelectValue` can resolve a label). It has no `onKeyDown`, `tabIndex`, `asChild` or `preventDefault` anywhere, the trigger is a real `<button>`, and Base UI runs `useListNavigation` without `virtual` — so items take real DOM focus and typeahead works. Driven from the keyboard it opens on Enter, moves on the arrow keys, selects on Enter, closes on Escape, and returns focus to its trigger, inside a Dialog as well as outside one. The 23 native `<select>` elements in the server-rendered filter forms are, of course, also fine.

**`PersonPicker` was the real defect.** `src/app/portal/(app)/people/person-picker.tsx` was an `<Input>` followed by a flat list of `<button>`s, reached from 42 files. No `role="combobox"`, no `role="listbox"`/`option`, no `aria-expanded`/`aria-controls`/`aria-activedescendant`, no arrow keys, no Escape, no accessible name on the input (the `FieldLabel`s around it carry no `htmlFor`), and no announcement when a person was picked. Focus also dropped to `<body>` whenever the field swapped for the selected chip or back. It is now built on Base UI's `Autocomplete`, in normal document flow so it stays inside the focus trap of the dialog or sheet that holds it.

**Why nothing caught it.** axe cannot see keyboard operability, and before this the repo held a total of five keyboard assertions, every one of them an Escape press. `src/components/ui/select.dom.test.tsx`, the `keyboard` block in `person-picker.dom.test.tsx`, and the palette's arrow-key test are the guard against the next regression.

**Still open.** The `<FieldLabel htmlFor>` sweep for picker call sites (the `aria-label` fallback covers them for now), and [#659](https://github.com/rcruzmcd/coven/issues/659) / [#663](https://github.com/rcruzmcd/coven/issues/663), which cover the wider manual keyboard and screen-reader pass.
